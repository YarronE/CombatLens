# Whole-game architecture

Use an optional run-local `game-study.json` (`combatlens-game-study/1`) bound to game_build and the exact research package fingerprint. It holds systems, lifecycle steps, bounded question/evidence cards, table descriptors, relationship rules, projection frame definitions and build slot metadata. Source JSON remains in the registered repository. Each descriptor chooses a source_id, JSON pointer, exact row shape and dependency_ids; adapter declarations never execute code in the server.

Add `/api/game-study` metadata, `/api/game-study/rows?table=&q=&offset=&limit=`, and `/api/game-study/record?table=&ordinal=`. A per-repository service uses bounded LRU document caches and source identity checks. Search spans native ID, annotation and raw fields; paginated lists return compact fields. Record detail includes selected/raw fields, provenance and resolved forward references. Explicit field/table rules preserve ambiguity; no suffix/fuzzy joins or universal schema assumptions. JSON pointers are reused from the design-study module. Table ordinals are stable within a hash-pinned source.

The shared `game.html`, `game.js`, and `game.css` use existing typography, dark surfaces and restrained accent. A left system list, central evidence browser and right selection inspector replace marketing content for this task. A lifecycle overview links systems; map projection and A/B build notebook are dedicated modes. Existing viewer/home links remain reachable and workspace-relative. DOM text nodes render source material safely. URL state restores system/table/row; request gates discard late loads. Build state stays client-side, scoped by package fingerprint, and is explicitly analyst-authored.

The private adapter adds original raw parameter/definition/reader dependencies, official guide excerpts with dated scope, and current export hashes. Additional decoding writes under ignored local, never into the source research project or game. The pilot retains its fixed snapshot; public information does not silently update that snapshot. Native static flags and weights do not prove availability or runtime frequencies. Large all-game animation recovery and full simulation are independent future work.
