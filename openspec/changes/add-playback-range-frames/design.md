# Design
## Inputs and constraints
User-provided screenshot is the approved continuation of v0.4's fused editor, with explicit request to remove small text and avoid unrequested functionality. Follow 05_Personal-Style and frontend rules: black focus, restrained existing game accent, Swiss alignment, one core task, no decorative subtitles. No new visual direction or art generation needed. The current task explicitly authorizes these local changes; no Plan-mode approval gate was entered.
## Structure
Keep central viewport + divider + sequencer. Transport: Play, previous/next frame, Loop, Range disclosure, speed, current coordinate. One timeline controls row: Timeline/Graph, seconds/frame selector, analysis snap, zoom/fit. Range appears as a thin bar/handles above ticks, without shading the full scene. Inspector contains event form and existing animation/source details. Move build/selection summaries and normal preview limitations into collapsed details; view tools into a disclosure. Use 13px control labels and 12px axis/event labels, not more tiny type.
Palette: existing dark #17191c/#24272b/#343941, readable #e1e6eb and registered game accent. Existing licensed Oxanium for identity/readout, system sans for controls. No additional fonts, illustrations, pages or unrelated features.
## Implementation
D1 Extend PlaybackClock with positive clip-second range and loop. Configure resets range/loop, sourceRate continues applying once. Tick wraps modulo length or stops exactly at end. Absolute seek stays independent, allowing paused inspection outside the playback range.
D2 Frame helpers use ONLY registered sample_times_seconds, not a guessed uniform grid or union of sparse channel keys. Binary search maps sample index to/from clip seconds; index interpolation is display-only. No source FPS inferred. Keep fallback source keys for existing sample/camera internals; frame stepping disabled without registered samples.
D3 AssetViewer owns range/loop/frame unit UI and emits a signature on clip/control changes so app.js updates the ruler/selection only when needed, never at every playback tick. Range numeric controls apply both values once, reading action seconds or sample-frame indexes using the proven mapping; fractional indexes interpolate between adjacent registered times and preserve an existing subframe selection; original event units stay unchanged. Proven segment bounds gate Timeline controls. Context/clip changes reset selection and loop, invalid form input restores previous values with a visible message.
D4 Draw a range bar and two accessible endpoints inside SVG; CTM conversion uses actual width/scroll. Pointer capture previews seek and commits on release; Escape/lost capture restores prior range and time. Arrow keys adjust an endpoint by one registered sample or the existing fine unit, bounded against reversal. Range gestures never enter event history.
D5 Seconds/frame ruler labels share the same action-second X geometry. Integer sample indices produce frame ticks at their mapped positions. Existing event math and history remain source-based. Shared cursor readout switches units with the ruler. Zoom and scrolling preserve range/time.
D6 Keep error messages visible; move normal limitations into source proof, and summary fields into collapsed action info. Keep files/graph/source tools accessible without adding functionality. Never drop pending event form on asynchronous clip/ruler refresh: defer render until safe.
## Validation
Pure clock/range/frame tests for modulo, exact end, rates, cancellation and no-FPS boundaries plus existing regressions. Actual browser: rate-one and rate-two samples, range ends/loop repetition, pointer+keyboard selection, invalid range, switching context, event undo/save, layout/scroll/draft protection and no-model synthetic fallback. Screenshots and case evidence stay local. Public scans and verified remote SHA conclude delivery.
