# Design

Store optional `reading` data inside the existing fingerprint/build-bound game-study overlay, so frozen packages already preserve it. A generic resolver accepts bounded facts from registered source excerpts, selected native row fields and declarative table measures (count or distinct count with scalar equality conditions). It evaluates no code and accepts no precomputed case results. Each fact carries source SHA, pointer or table scope and underlying dependencies.

Each chapter references fact IDs. Only when all required facts are current may its analyst paragraphs, tradeoff rows, conceptual connection and conditional scenarios display. Diagnostic titles, validation questions and gaps remain available on failure. Unknown source kinds cannot be promoted to official statements. Null/missing, physical ordinal, duplicate IDs and scalar types retain existing semantics.

The reading view uses a chapter directory, a compact selectable play-loop diagram and a focused article. Evidence appears in the existing right panel; raw record buttons lead to existing queries. Reading state is hash-addressable. Contextual configuration and Build links connect to the existing views. Styling extends the current dark workspace without replacing its editor.

Case evidence and writing stay in the local adapter; generic logic, contracts and synthetic tests enter public Git. Source projects remain read only. The snapshot is unchanged and newer guide statements do not establish runtime compatibility.
